Text Selections

The ::selection pseudo-element styles the portion of text that the user highlights with the mouse or keyboard. It is commonly used to change the selected text color and background color, and it follows a special inheritance model for highlighted content.

Only a limited set of CSS properties work with ::selection, including color, background-color, text-decoration, and text-shadow. The background-image property is ignored, so selection styling should stay simple and readable.

Basic syntax

You can style all selected text on the page like this:

::selection {
                                  color: #faf5ee;
                                  background-color: #d76b00;
                                }

You can also target specific elements:

p::selection {
                                  color: #fff;
                                  background-color: #795548;
                                }

This is useful if you want your framework to offer named selection utilities such as ic-brown-selection, ic-blue-selection, and ic-green-selection.

How it works :

When a user selects text, the browser applies your ::selection styles only to the highlighted part. This makes it different from normal class styling, because it only appears during selection and then disappears when the user clicks elsewhere

If you define ::selection on the page root, it affects the whole document unless a more specific selection rule overrides it. That means you can create a default framework selection color, then provide utility classes for special cases.

Utility class approach

Since your framework uses the ic- prefix, a good pattern is to create classes like these:

.ic-brown-selection::selection { color:#fff; background-color:#795548; }
                                .ic-amber-selection::selection { color:#000; background-color:#ffc107; }
                                .ic-blue-selection::selection { color:#fff; background-color:#2196f3; }

Font Weights

The Iconic Framework provides a robust, high-performance set of typography utilities designed for precise typographic control. These global classes map human-readable design terms directly to the W3C standard 100–900 numerical font-weight spectrum.

By leveraging the !important flag, these helper utilities guarantee deterministic layout styling by instantly overriding default element properties or nested component hierarchies.

References

According to the Mozilla Developer Network (MDN), the font-weight property controls the degree of blackness or stroke thickness of glyphs inside a font family.

  • Fallback Algorithm: MDN notes that if a font file does not contain an explicit weight layer (e.g., you request .ic-medium (500) but only 400 and 700 are available), the browser uses a standardized matching fallback. Generally, weights of 400 to 500 fallback to each other, while weights below 400 target lighter matches, and weights above 500 target heavier matches.
  • Keyword Matching: MDN natively maps the global browser keyword normal to 400 and bold to 700.

Compiled Width: width: 100% !important; margin-left: auto !important; margin-right: auto !important;Maximum Bound: max-width: 61.25rem !important;Purpose: Establishes the core structural editorial viewport width, mathematically optimized for scanning long rows of type comfortably.

.ic-content-sm

Maximum Bound: max-width: 40rem !important;Purpose: Restricts layouts to a narrow reading column. Best used for dense documentation essays, privacy policy segments, and single-column blog entries.

.ic-content-md

Maximum Bound: max-width: 48rem !important;Purpose: Provides a medium width threshold. Ideal for focused product review layouts or centered text grids that sit alongside side illustrations.

.ic-content-lg

Maximum Bound: max-width: 61.25rem !important;Purpose: Establishes a wide reading width for long-form content. purpose is to provide a wide viewport for wide layouts.

.ic-content-xl

Maximum Bound: max-width: 75rem !important;Purpose: Establishes a wide reading width for long-form content.
