## ✨ What Is Iconic?

**Iconic** is a clean, consistent, dependency-free icon library and CSS utility framework built for modern web development. It provides **19,000+ carefully crafted SVG icons** rendered entirely through CSS — no JavaScript runtime, no build step, no framework lock-in.

Iconic is designed for teams and developers who want a stable icon system that feels lightweight yet remains complete. Whether you are building a landing page, a dashboard, a documentation site, or a production-grade application, Iconic gives you the icons and CSS utilities you need with a single predictable API.

### The Problem Iconic Solves

Most icon libraries force you into one of these situations:

- **Heavy JavaScript bundles** just to render icons on screen.
- **Build-step requirements** that slow down prototyping and simple projects.
- **Framework-specific packages** that tie your icon system to React, Vue, or Angular.
- **Inconsistent naming** that makes it impossible to guess a class name.
- **Limited icon sets** that force you to mix multiple libraries.
- **No utility classes** for spacing, sizing, or styling icons alongside your content.

Iconic eliminates all of these problems with a single, elegant approach:

1. **One custom element**: `<i-ic>` — semantic, accessible, and familiar.
2. **One predictable prefix**: `ic-` — guess the class name on your first try.
3. **Zero JavaScript** at runtime — icons render through pure CSS `mask-image`.
4. **Thousands of icons** across every category you can think of.
5. **A full utility framework** for sizing, coloring, animating, and positioning icons.
6. **A comprehensive CSS framework** for typography, layout, colors, spacing, and responsive design.

<details>
<summary><strong>⚡ Zero Runtime Overhead</strong></summary>

Icons render through **pure CSS** using `mask-image` and the `currentColor` property. There is:

- **No JavaScript runtime** — icons work even with JavaScript disabled
- **No hydration cost** — perfect for server-side rendered applications
- **No framework dependency** — works in any HTML environment
- **No build step required** — drop in the CSS file and start using icons immediately

The rendering technique uses CSS custom properties to define each icon's SVG path as a mask, which means the browser handles all the rendering natively with hardware acceleration.

</details>

<details>
<summary><strong>🎯 Single Predictable API</strong></summary>

Every icon in Iconic follows the exact same pattern:

```html
<!-- Two classes: base class + icon name -->
<i-ic class="ic ic-home"></i-ic>
```

- **`ic`** — the base class, required on every icon element
- **`ic-{name}`** — the specific icon identifier (e.g., `ic-home`, `ic-search`, `ic-arrow-left`)
- **`ic-{modifier}`** — optional modifiers for size, color, animation, etc.

Icon names are lowercase, words are separated by a single hyphen, and names describe the object or action they represent. This means you can usually **guess an icon's class name correctly on your first try**.

</details>

<details>
<summary><strong>📐 24×24 Consistent Grid</strong></summary>

Every icon is designed on a consistent **24×24 base grid** with:

- Uniform stroke width across all icons
- Optical sizing adjustments for visual balance
- Consistent corner radius conventions
- Matching visual weight between outlined and filled variants
- Retina-ready vector rendering at any resolution

This consistency means you can mix icons from different categories in the same toolbar, navigation, or list and they will always look cohesive.

</details>

- **Entrance**: `ic-fade-in`, `ic-slide-up`, `ic-slide-down`, `ic-slide-left`, `ic-slide-right`, `ic-zoom-in`, `ic-rotate-in`, `ic-pop-in`

All animations automatically respect the user's `prefers-reduced-motion` setting.

## 📦 Installation

Iconic can be installed in multiple ways depending on your project setup. Choose the method that works best for you.

### CDN (Fastest)

The fastest way to get started. Add a single `<link>` tag to your HTML `<head>`:

```html
<!-- Iconic Icon Library (Core) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@2.0.0/iconic.min.css">

<!-- Iconic Utility Classes (Optional — animations, spacing, filters, etc.) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@2.0.0/iconic-utility.css">

<!-- Iconic Framework (Optional — full CSS framework with layout, colors, typography, etc.) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@2.0.0/iconic-framework.css">
```

> **Tip:** For most projects, the core `iconic.min.css` is all you need. Add the utility and framework files only when you need their additional features.

### NPM

```bash
npm install iconic-icons
```

## 🎯 Icon Reference

This section documents everything you need to know about using icons in your project.

### Basic Usage

Every icon in Iconic uses the same simple pattern — a custom element `<i-ic>` with two classes:

```html
<!-- The base class 'ic' is always required -->
<!-- The second class 'ic-{name}' determines which icon is displayed -->

<i-ic class="ic ic-home"></i-ic>
<i-ic class="ic ic-search"></i-ic>
<i-ic class="ic ic-settings"></i-ic>
<i-ic class="ic ic-google"></i-ic>
<i-ic class="ic ic-github"></i-ic>
<i-ic class="ic ic-arrow-left"></i-ic>
<i-ic class="ic ic-shopping-cart"></i-ic>
```

That is the entire API. No wrapper components, no props, and no configuration needed for the default case.

> **Why `<i-ic>`?** The custom element `<i-ic>` is semantically meaningful (it represents an icon), works as a custom HTML element, and avoids class name collisions with existing CSS frameworks.

### Class Naming Convention

Iconic follows one predictable pattern:

| Class Pattern | Purpose | Example |
|---------------|---------|---------|
| `ic` | Base class (required) | `<i-ic class="ic ic-home">` |
| `ic-{name}` | Icon identifier | `ic-home`, `ic-search`, `ic-arrow-left` |
| `ic-{size}` | Size modifier | `ic-sm`, `ic-lg`, `ic-2xl`, `ic-3x` |
| `ic-{color}` | Color modifier | `ic-primary`, `ic-success`, `ic-danger` |
| `ic-{animation}` | Animation modifier | `ic-spin`, `ic-pulse`, `ic-bounce` |
| `ic-{transform}` | Transform modifier | `ic-rotate-90`, `ic-flip-x`, `ic-scale-150` |

**Naming rules:**

- Icon names are **lowercase**
- Words are separated by a **single hyphen** (`-`)
- Names describe the **object or action** they represent
- Brand icons use recognizable short names: `ic-google`, `ic-github`, `ic-figma`, `ic-discord`
- You can usually guess an icon's class name on the first try

### Sizes

Iconic ships with multiple sizing systems. By default, icons inherit `font-size` from their parent element, so they scale naturally with surrounding text.

#### Named Sizes

| Class | Computed Size | Typical Use |
|-------|--------------|-------------|

| `ic-xs` | 0.75em (12px) | Dense inline text, small badges |
| `ic-sm` | 0.875em (14px) | Inline with body text, form fields |
| `ic-md` | 1em (16px) | Default size, standard UI |
| `ic-lg` | 1.25em (20px) | Section headers, list leading icons |
| `ic-xl` | 1.5em (24px) | Feature callouts, empty states |
| `ic-2xl` | 2em (32px) | Hero sections, marketing pages |
| `ic-3xl` | 3em (48px) | Large displays, presentations |

## ♿ Accessibility

Iconic is designed with accessibility as a first-class concern. This section documents the accessibility features and best practices.

### Decorative Icons

When an icon sits next to visible text that already conveys the meaning, hide it from assistive technology:

```html
<button>
  <i-ic class="ic ic-trash" aria-hidden="true"></i-ic>
  Delete item
</button>

<a href="/settings">
  <i-ic class="ic ic-settings" aria-hidden="true"></i-ic>
  Settings
</a>
```

### Meaningful Icons

When the icon is the only content (no visible text label), provide an accessible name:

```html
<!-- Using aria-label on the parent -->
<button aria-label="Delete item">
  <i-ic class="ic ic-trash" aria-hidden="true"></i-ic>
</button>

<!-- Using a title attribute -->
<i-ic class="ic ic-home" role="img" title="Home page"></i-ic>
```

### ARIA Support

Iconic supports standard ARIA attributes on the `<i-ic>` element:

| Attribute | Purpose | Example |
|-----------|---------|---------|
| `aria-hidden="true"` | Hide from screen readers | Decorative icons |
| `aria-label="text"` | Provide accessible name | Meaningful standalone icons |
| `role="img"` | Declare as image | Standalone meaningful icons |
| `role="button"` | Declare as button | Interactive icons |
| `aria-disabled="true"` | Mark as disabled | Disabled state |
| `aria-busy="true"` | Mark as loading | Loading states |
| `tabindex="0"` | Make focusable | Keyboard-navigable icons |

### Keyboard Navigation

Icons with `role="button"` or `tabindex` are keyboard-accessible:

```html
<!-- Focusable icon button -->
<i-ic class="ic ic-close ic-interactive" role="button" tabindex="0"
      aria-label="Close dialog"
      onkeydown="if(event.key==='Enter'||event.key===' '){closeDialog()}">
</i-ic>
```

### Focus Management

Iconic provides visible focus indicators for keyboard users:

```css
/* Default focus styles built into Iconic */
i-ic:focus-visible {
  outline: 2px solid currentColor;
  outline-offset: 0.15em;
  border-radius: 0.15em;
}

/* Icons with role="button" get a larger offset */
i-ic[role="button"]:focus-visible {
  outline-offset: 3px;
}
```

### Screen Readers

The `<i-ic>` custom element is recognized by modern screen readers. Combined with proper ARIA attributes, icons can be accurately announced:

```html
<!-- Announced as "Success, icon" -->
<i-ic class="ic ic-check-circle ic-success" role="img" aria-label="Success"></i-ic>

<!-- Completely hidden from screen readers -->
<i-ic class="ic ic-decorative-flourish" aria-hidden="true"></i-ic>
```

### Contrast & Visibility

Iconic's semantic colors are tested for WCAG AA compliance in their default configurations:

- **Primary** (`#2563eb` on white) — 4.6:1 contrast ratio ✓
- **Success** (`#16a34a` on white) — 4.5:1 contrast ratio ✓
- **Danger** (`#dc2626` on white) — 4.6:1 contrast ratio ✓
- **Warning** (`#d97706` on white) — 3.9:1 (use with text, not alone)
- **Info** (`#0891b2` on white) — 4.5:1 contrast ratio ✓

In high-contrast mode (`forced-colors: active`), icons automatically switch to `CanvasText` color for maximum visibility.

### Reduced Motion

All animations in Iconic automatically respect the user's `prefers-reduced-motion` setting:

```css
/* Built into Iconic — all animations are disabled when the user prefers reduced motion */
@media (prefers-reduced-motion: reduce) {
  :where(i-ic),
  :where(i-ic)::after {
    animation: none !important;
    transition: none !important;
  }
}
```

You can also explicitly control this with utility classes:

```html
<!-- Force disable animations regardless of user preference -->
<i-ic class="ic ic-spinner ic-motion-reduce"></i-ic>

<!-- Only animate when the user has not requested reduced motion -->
<i-ic class="ic ic-star ic-motion-safe ic-pulse"></i-ic>
```

### Graceful Degradation

In browsers that do not support `mask-image` (very old browsers), Iconic provides a `@supports` fallback that hides the icon rather than showing a broken state:

    display: none;
  }
}

## ⚡ Performance

### Zero Runtime Cost

Iconic adds **zero JavaScript** to your runtime. All icon rendering is handled by CSS, which means:

- No JavaScript parsing or execution time
- No framework hydration cost
- No DOM manipulation overhead
- Icons work even with JavaScript disabled

### Efficient Rendering

- Icons are rendered via CSS `mask-image`, which leverages the browser's native compositing pipeline
- The `contain: paint` property on each icon element enables render optimization
- `will-change: transform, opacity, filter` hints the browser to optimize for animation
- `backface-visibility: hidden` prevents unnecessary repaints

### Caching

- The CSS file is a single cacheable asset
- Icon definitions use CSS custom properties, so changing a variable does not require a new file download
- The `:where()` selector has zero specificity, eliminating the need for overrides

### Bundle Size

| File | Minified | Gzipped (approx) |
|------|----------|-------------------|
| `iconic.min.css` | ~1.31 MB | ~150 KB |
| `iconic-utility.css` | ~50 KB | ~8 KB |
| `iconic-framework.css` | ~1.4 MB | ~160 KB |

### Optimization Tips

1. **Only load what you need** — If you only need icons, load `iconic.min.css` alone
2. **Use the CDN** — jsDelivr provides global edge caching
3. **Enable compression** — Gzip or Brotli compression significantly reduces transfer size
4. **Subset your icons** — For performance-critical builds, generate a CSS file with only the icons you use
5. **Preload critical icons** — Use `<link rel="preload">` for icons needed above the fold

## 📖 Migration Guide

### From v1.x to v2.0

Version 2.0 introduces the `ic-` prefix (replacing `icon-`). Here is how to migrate:

| v1.x | v2.0 | Notes |
|------|------|-------|
| `<i class="icon icon-home">` | `<i-ic class="ic ic-home">` | Element changed to `<i-ic>` |
| `icon-home` | `ic-home` | Prefix changed |
| `icon-2x` | `ic-2x` | Size class prefix changed |
| `icon-spin` | `ic-spin` | Animation class prefix changed |
| `icon-red` | `ic-danger` | Color names changed to semantic |

**Automated migration (find and replace):**

```bash
# Replace the element
find . -name "*.html" -exec sed -i 's/<i class="icon /<i-ic class="ic /g' {} \;

# Replace the prefix
find . -name "*.html" -exec sed -i 's/icon-/ic-/g' {} \;
```

## ✅ Best Practices

Follow these professional recommendations to get the most out of Iconic in production.

### 1. Always Use the Base Class

Every icon **must** have the `ic` base class. Without it, the icon will not render:

```html
<!-- ✅ Correct -->
<i-ic class="ic ic-home"></i-ic>

<!-- ❌ Missing base class — icon will not render -->
<i-ic class="ic-home"></i-ic>
```

### 2. Use `aria-hidden` for Decorative Icons

When an icon sits next to text that already conveys the meaning, hide it from screen readers:

```html
<!-- ✅ Correct -->
<button>
  <i-ic class="ic ic-trash" aria-hidden="true"></i-ic>
  Delete
</button>

<!-- ❌ Screen reader will announce "trash icon, delete" redundantly -->
<button>
  <i-ic class="ic ic-trash"></i-ic>
  Delete
</button>
```

### 3. Provide Labels for Standalone Icons

When an icon has no accompanying text, give it an accessible name:

```html
<!-- ✅ Correct -->
<button aria-label="Delete item">
  <i-ic class="ic ic-trash" aria-hidden="true"></i-ic>
</button>

<!-- ❌ Screen reader cannot convey the icon's purpose -->
<button>
  <i-ic class="ic ic-trash"></i-ic>
</button>
```

### 4. Pin Your CDN Version

Always use a specific version in production, not `@latest`:

```html
<!-- ✅ Pinned version -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@2.0.0/iconic.min.css">

<!-- ❌ Latest can change unexpectedly -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@latest/iconic.min.css">
```

### 5. Use Semantic Color Classes

Prefer semantic colors over hardcoded values:

```html
<!-- ✅ Semantic — adapts to theme changes -->
<i-ic class="ic ic-check ic-success"></i-ic>

<!-- ⚠️ Hardcoded — won't adapt to dark mode -->
<i-ic class="ic ic-check" style="color: #16a34a;"></i-ic>
```

### 6. Load Only What You Need

If you only need icons, do not load the utility and framework files:

```html
<!-- ✅ Minimal load — icons only -->
<link rel="stylesheet" href="iconic.min.css">

<!-- ⚠️ Full load — only if you need framework utilities -->
<link rel="stylesheet" href="iconic.min.css">
<link rel="stylesheet" href="iconic-utility.css">
<link rel="stylesheet" href="iconic-framework.css">
```

### 7. Use the `<i-ic>` Element

The custom element provides better semantics and avoids class name collisions:

```html
<!-- ✅ Custom element -->
<i-ic class="ic ic-home"></i-ic>

<!-- ⚠️ Generic element — may collide with other CSS -->
<span class="ic ic-home"></span>
```

### 8. Combine Utilities Intentionally

Build up complex icon presentations by combining utility classes:

```html
<!-- A polished icon badge -->
<i-ic class="ic ic-check ic-bg-success ic-light ic-p-3 ic-rounded-full ic-3x ic-shadow-md ic-pop-in"></i-ic>
```

### 9. Test with Reduced Motion

Verify your interface works correctly when animations are disabled:

1. Open your browser's accessibility settings
2. Enable "Reduce motion" or "Prefer reduced motion"
3. Verify all icons and UI elements still function correctly

### 10. Use Consistent Sizing

Within the same context (a toolbar, a list, a navigation), use the same icon size:

```html
<!-- ✅ All icons in this toolbar are the same size -->
<nav style="display: flex; gap: 1rem;">
  <i-ic class="ic ic-home ic-lg"></i-ic>
  <i-ic class="ic ic-search ic-lg"></i-ic>
  <i-ic class="ic ic-settings ic-lg"></i-ic>
</nav>

<!-- ❌ Mixed sizes look inconsistent -->
<nav style="display: flex; gap: 1rem;">
  <i-ic class="ic ic-home ic-sm"></i-ic>
  <i-ic class="ic ic-search ic-3x"></i-ic>
  <i-ic class="ic ic-settings ic-lg"></i-ic>
</nav>
```

## ❌ Common Mistakes

### Mistake 1: Forgetting the Base Class

```html
<!-- ❌ Wrong — missing 'ic' base class -->
<i-ic class="ic-home"></i-ic>

<!-- ✅ Correct -->
<i-ic class="ic ic-home"></i-ic>
```

### Mistake 2: Using the Wrong Element

```html
<!-- ❌ Wrong — generic element -->
<div class="ic ic-home"></div>

<!-- ✅ Correct — semantic custom element -->
<i-ic class="ic ic-home"></i-ic>
```

### Mistake 3: Not Providing Accessibility Labels

```html
<!-- ❌ Wrong — screen reader cannot convey meaning -->
<button><i-ic class="ic ic-close"></i-ic></button>

<!-- ✅ Correct — accessible name provided -->
<button aria-label="Close dialog"><i-ic class="ic ic-close" aria-hidden="true"></i-ic></button>
```

### Mistake 4: Using `@latest` in Production

```html
<!-- ❌ Can break when new versions are released -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@latest/iconic.min.css">

<!-- ✅ Pinned to a specific version -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@2.0.0/iconic.min.css">
```

### Mistake 5: Overriding Variables on the Wrong Element

```css
/* ❌ Wrong — setting on body doesn't cascade to icon internals */
body {
  --ic-size: 2em;
}

/* ✅ Correct — set on the icon or a parent wrapper */
.my-icons i-ic {
  --ic-size: 2em;
}
```

### Mistake 6: Using `class` in React Instead of `className`

```jsx
// ❌ Wrong in React
<i-ic class="ic ic-home" />

// ✅ Correct in React
<i-ic className="ic ic-home" />
```

### Mistake 7: Mixing v1 and v2 Class Prefixes

```html
<!-- ❌ Wrong — mixing old and new prefix -->
<i-ic class="ic icon-home"></i-ic>

<!-- ✅ Correct — all ic- prefix -->
<i-ic class="ic ic-home"></i-ic>
```

### Mistake 8: Animating Non-Interactive Elements Without Purpose

```html
<!-- ❌ Distracting animation on static content -->
<p><i-ic class="ic ic-info ic-spin"></i-ic> Please read the documentation.</p>

<!-- ✅ Purposeful animation -->
<i-ic class="ic ic-spinner ic-spin ic-lg"></i-ic> Loading results...
```

### Mistake 9: Ignoring RTL Layout

```html
<!-- ❌ This arrow always points left, even in RTL -->
<i-ic class="ic ic-arrow-left"></i-ic>

<!-- ✅ Use flip for RTL or use logical direction -->
<div dir="rtl">
  <i-ic class="ic ic-arrow-left ic-flip-x"></i-ic>
</div>
```

### Mistake 10: Not Testing in Dark Mode

If your app supports dark mode, test all icons in both light and dark themes to ensure sufficient contrast and readability.

## ❓ FAQ

<details>
<summary><strong>1. What is Iconic?</strong></summary>

Iconic is an open-source icon library and CSS utility framework that provides 19,000+ pixel-perfect SVG icons rendered entirely through CSS. It includes a comprehensive utility system for sizing, coloring, animating, and positioning icons, as well as a full CSS framework for building web pages.

</details>

<details>
<summary><strong>2. Is Iconic free to use?</strong></summary>

Yes. Iconic is released under the MIT License, which means it is completely free for personal, commercial, and open-source projects. Attribution is appreciated but not required.

</details>

<details>
<summary><strong>3. Do I need JavaScript to use Iconic?</strong></summary>

No. Iconic works entirely through CSS with zero JavaScript runtime. Icons are rendered using CSS `mask-image` and custom properties. The gallery site includes JavaScript for search and interaction, but the icon library itself is pure CSS.

</details>

<details>
<summary><strong>4. How many icons does Iconic include?</strong></summary>

Iconic includes over 19,000 icons across 30+ categories, including navigation, UI, communication, files, media, commerce, people, weather, maps, charts, security, social/brand, transportation, food, medical, education, sports, animals, and more.

</details>

<details>
<summary><strong>5. Can I use Iconic with React?</strong></summary>

Yes. Iconic works with React by using `className` instead of `class`. No special wrapper component is needed:

```jsx
<i-ic className="ic ic-home ic-lg" aria-hidden="true" />
```

</details>

<details>
<summary><strong>6. Does Iconic support dark mode?</strong></summary>

Yes. Add `data-theme="dark"` to any ancestor element, and all semantic color variables automatically switch to dark-mode-optimized values.

</details>

<details>
<summary><strong>7. What is the `<i-ic>` element?</strong></summary>

`<i-ic>` is a custom HTML element (Web Component) used for rendering icons. It is semantically meaningful, avoids class name collisions with other CSS frameworks, and provides a clean API: `<i-ic class="ic ic-home"></i-ic>`.

</details>

<details>
<summary><strong>8. Why use `<i-ic>` instead of `<i>` or `<span>`?</strong></summary>

The `<i-ic>` custom element provides better semantics, avoids conflicts with CSS frameworks that style `<i>` or `<span>` elements, and allows Iconic to apply styles specifically to icon elements without affecting other parts of your UI.

</details>

<details>
<summary><strong>9. Can I self-host Iconic?</strong></summary>

Yes. Download the CSS files from the repository or releases page and serve them from your own infrastructure. This is recommended for production applications that need full control over caching and deployment.

</details>

<details>
<summary><strong>10. What browsers does Iconic support?</strong></summary>

Iconic supports all modern evergreen browsers: Chrome 80+, Firefox 80+, Safari 14+, Edge 80+, Opera 67+, and their mobile equivalents. The icon system uses CSS `mask-image` with a `@supports` fallback for older browsers.

</details>

<details>
<summary><strong>11. How do I update to a new version?</strong></summary>

If using the CDN, change the version number in the URL. If using NPM, run `npm update iconic-icons`. Always check the changelog for breaking changes before updating major versions.

</details>

<details>
<summary><strong>12. Can I request a new icon?</strong></summary>

Yes! Open a GitHub Issue with the icon name or a reference image/link. New icons are typically added within 24 hours.

</details>

<details>
<summary><strong>13. Is Iconic accessible?</strong></summary>

Yes. Iconic supports ARIA attributes, keyboard navigation, screen readers, high contrast mode, and reduced motion preferences. See the [Accessibility](#-accessibility) section for detailed guidance.

</details>

<details>
<summary><strong>14. How does the icon rendering work?</strong></summary>

Each icon's SVG path is stored as a CSS custom property (`--ic-url`). The `::after` pseudo-element uses `mask-image` with this URL to render the icon shape, and `background: currentColor` fills it with the current text color. This approach requires zero JavaScript and renders at native speed.

</details>

<details>
<summary><strong>15. Can I customize the icons?</strong></summary>

Yes. Every visual aspect of an icon can be customized through CSS custom properties: size, color, rotation, scale, flip, shadow, glow, filters, borders, backgrounds, animations, and more.

</details>

<details>
<summary><strong>16. Does Iconic work offline?</strong></summary>

Yes. After the CSS file is downloaded (via NPM, Git clone, or manual download), icons work completely offline with no external dependencies.

</details>

<details>
<summary><strong>17. How do I make an icon interactive?</strong></summary>

Add the `ic-interactive` class for built-in hover and active effects, or add `role="button"` and `tabindex="0"` for keyboard accessibility:

```html
<i-ic class="ic ic-trash ic-interactive ic-danger" role="button" tabindex="0"></i-ic>
```

</details>

<summary><strong>18. Can I stack icons?</strong></summary>

Yes. Use the `ic-stack` container class with `ic-stack-1x` and `ic-stack-2x` for layered icons:

```html
<span class="ic ic-stack">
  <i-ic class="ic ic-circle ic-stack-2x ic-bg-primary"></i-ic>
  <i-ic class="ic ic-check ic-stack-1x ic-light"></i-ic>
</span>
```

</details>

<details>
<summary><strong>19. What is the difference between `iconic.css`, `iconic-utility.css`, and `iconic-framework.css`?</strong></summary>

- `iconic.css` / `iconic.min.css` — Core icon definitions (19,000+ icons with mask-image paths)
- `iconic-utility.css` — Utility classes for icons: spacing, animations, filters, responsive, hover states
- `iconic-framework.css` — Full CSS framework: reset, fonts, colors, grid, spacing, typography, layout

Load only the files you need.

## 🔧 Troubleshooting

### Icons Not Rendering

**Problem:** Icons appear as blank squares or do not show up at all.

**Solutions:**

1. **Check the base class** — Every icon must have the `ic` class:
   ```html
   <!-- ❌ Missing -->
   <i-ic class="ic-home"></i-ic>
   <!-- ✅ Correct -->
   <i-ic class="ic ic-home"></i-ic>
   ```

2. **Check the CSS file is loaded** — Open DevTools > Network tab and verify `iconic.min.css` loaded with a 200 status.

3. **Check the icon name** — Verify the icon exists in the gallery. Class names are case-sensitive:
   ```html
   <!-- ❌ Wrong case -->
   <i-ic class="ic ic-Home"></i-ic>
   <!-- ✅ Correct -->
   <i-ic class="ic ic-home"></i-ic>
   ```

4. **Check browser support** — Iconic requires `mask-image` support. Chrome 80+, Firefox 80+, Safari 14+, Edge 80+.

### Icons Appear at Wrong Size

**Problem:** Icons are too large or too small.

**Solutions:**

1. **Icons inherit font-size** — If the parent element has an unusual `font-size`, the icon will match it. Add a size class:
   ```html
   <i-ic class="ic ic-home ic-md"></i-ic>
   ```

2. **Check for conflicting CSS** — Another stylesheet might be overriding `--ic-size`. Use DevTools to inspect the computed value.

### Animations Not Working

**Problem:** Animation classes have no visible effect.

**Solutions:**

1. **Check `prefers-reduced-motion`** — If your OS has reduced motion enabled, all Iconic animations are automatically disabled.

2. **Ensure the utility CSS is loaded** — Animations are defined in `iconic-utility.css`:
   ```html
   <link rel="stylesheet" href="iconic-utility.css">
   ```

3. **Check for animation conflicts** — Another CSS rule might override the animation property.

### Colors Not Changing

**Problem:** Color classes have no visible effect.

**Solutions:**

1. **Check specificity** — The `:where()` selector has zero specificity. Inline styles or higher-specificity selectors will override Iconic colors.

2. **Use `!important` if needed** — For one-off overrides:
   ```html
   <i-ic class="ic ic-home" style="color: red !important;"></i-ic>
   ```

3. **Check dark mode** — If `data-theme="dark"` is active, semantic colors switch to dark-mode values.

### Custom Element Not Recognized

**Problem:** Browser shows `<i-ic>` as an unknown element.

**Solutions:**

1. **This is normal** — Custom elements are valid HTML5. The browser renders them correctly even without JavaScript registering them.

2. **For older browsers** — Add a minimal registration:
   ```javascript
   customElements.define('i-ic', class extends HTMLElement {});
   ```

### Icons Not Aligned with Text

**Problem:** Icons appear misaligned when placed next to text.

**Solutions:**

1. **Use vertical alignment classes**:
   ```html
   <i-ic class="ic ic-home ic-middle"></i-ic> Aligned to middle
   <i-ic class="ic ic-home ic-baseline"></i-ic> Aligned to baseline
   ```

2. **Use flexbox on the parent**:
   ```html
   <div style="display: flex; align-items: center; gap: 0.5rem;">
     <i-ic class="ic ic-home"></i-ic>
     <span>Perfectly aligned</span>
   </div>
   ```

### CDN Not Loading

**Problem:** The jsDelivr CDN URL returns a 404 or timeout.

**Solutions:**

1. **Check the version number** — Ensure the version in the URL exists:
   ```html
   <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/junaidprodeveloper/Iconic@2.0.0/iconic.min.css">
   ```

2. **Try a different CDN mirror** — If jsDelivr is down, download the file and self-host it.

3. **Clear cache** — Your browser might have cached a failed response.

### Framework Classes Not Working

**Problem:** Classes like `ic-margin-4` or `ic-text-center` have no effect.

**Solutions:**

1. **Load the framework CSS** — These classes are defined in `iconic-framework.css`:
   ```html
   <link rel="stylesheet" href="iconic-framework.css">
   ```

2. **Check for specificity conflicts** — The framework uses `!important` on most utilities, but check for inline styles that might override them.

- JavaScript: ES6+ syntax, no external dependencies
- Documentation: Clear, professional English with examples

### Pull Request Guidelines

- Keep PRs focused on a single change
- Include before/after screenshots for visual changes
- Update documentation if you change behavior
- Follow the existing file structure and naming conventions

## 🔒 Security Policy

### Reporting a Vulnerability

If you discover a security vulnerability in Iconic, please report it responsibly:

1. **Do not** open a public GitHub issue
2. Email the maintainer at the contact address listed in the repository
3. Include a description of the vulnerability, steps to reproduce, and potential impact
4. Allow reasonable time for the issue to be addressed before public disclosure

### Security Practices

- Iconic is a CSS-only library with zero JavaScript runtime
- No data is collected, transmitted, or stored
- No external requests are made after the CSS file is loaded
- All icon rendering happens client-side through CSS
- The CDN is served over HTTPS with proper CORS headers
